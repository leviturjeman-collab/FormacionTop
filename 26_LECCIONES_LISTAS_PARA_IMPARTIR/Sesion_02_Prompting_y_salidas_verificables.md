# Prompting profesional, formatos, fuentes, criterios y revision critica

## Duracion recomendada

90 minutos. Si el grupo es principiante, dividir en dos sesiones de 60 minutos.

## Objetivo

Que el alumno termine con una pieza visible relacionada con esta sesion y pueda explicar como se usa, que limita y como se revisa.

## Agenda

1. Apertura con problema real.
2. Explicacion del modelo mental.
3. Demostracion guiada.
4. Practica individual.
5. Error provocado.
6. Reparacion.
7. Cierre y deberes.

## Materiales

Boveda de Obsidian, archivo de referencia, plantilla de entrega, acceso a herramienta si aplica y checklist de evaluacion.

## Practica

El alumno crea una version minima del entregable. Debe dejarlo documentado en Obsidian con objetivo, pasos y resultado.

## Error provocado

El profesor introduce una ambiguedad, dato faltante, fuente no verificada, permiso incorrecto o salida rota. El alumno diagnostica antes de corregir.

## Deberes

Convertir la practica en una nota limpia y enlazarla con el documento maestro o el capstone.

## Evaluacion

Se evalua claridad, ejecucion, diagnostico, documentacion y capacidad de explicar decisiones.
## Control editorial profesional

Este archivo forma parte de la capa final de producto de la academia. Su funcion es que **Prompting profesional, formatos, fuentes, criterios y revision critica** no sea solo una idea escrita, sino una pieza util para impartir, evaluar, vender, actualizar o entregar. El entregable asociado es: **sesion impartible**.

### Criterio de impecabilidad

Un archivo se considera impecable cuando una persona puede abrirlo sin explicacion externa, entender el objetivo, saber que necesita, ejecutar una accion, producir una salida, detectar errores comunes y defender el resultado. Si el archivo contiene informacion factual o tecnica, debe indicar fuentes y fecha de revision. Si contiene una plantilla interna, debe aclarar como usarla y que no debe prometer.

### Uso por nivel

Basico: el alumno entiende el concepto, completa una version simple y explica el resultado en lenguaje claro.

Intermedio: el alumno adapta la pieza a un caso real, documenta decisiones, identifica riesgos y prepara una entrega revisable.

Avanzado: el alumno convierte la pieza en parte de un sistema profesional con versionado, privacidad, evaluacion, mantenimiento y defensa.

### CHECK

Antes de usar este archivo, responder: que problema resuelve, para quien, que datos entran, que salida se espera, que fuente respalda la informacion, que podria salir mal y quien revisa.

### DO

Crear una version observable del entregable. Puede ser una checklist, examen, certificado, guion, presentacion, asset, workflow, documento legal, onboarding, caso de estudio o demo.

### BREAK

Probar un fallo controlado: falta de datos, herramienta incorrecta, fuente desactualizada, promesa excesiva, permiso mal definido, privacidad insuficiente, evaluacion ambigua o entregable incompleto.

### FIX

Documentar causa, evidencia, cambio y prevencion. No basta con arreglar el caso: hay que mejorar la plantilla, la rubrica, el proceso o el checklist para que el error no se repita.

### EXPLAIN

El alumno debe poder explicar que hizo, por que eligio esa solucion, que limite tiene, como se verifica y como lo mantendria. Si no puede explicarlo, todavia no es material premium.

### Que eliminar si sobra

Eliminar frases genericas que no ayuden a decidir, ejecutar, verificar, evaluar o entregar. En una version comercial, cada bloque debe tener una funcion clara: enseñar, guiar, prevenir, demostrar, evaluar o vender con honestidad.

### Proxima revision

Revisar antes de grabar una clase, entregar a un alumno, vender el modulo o cuando cambie una fuente oficial relacionada.
