# Fase 02 - Aplicacion a trabajo e ideas

## Objetivo de la fase

La segunda fase responde a la pregunta que hiciste: como aplico lo aprendido a mi trabajo y como llevo mis ideas a cabo. Esta es la fase donde la IA deja de ser tema de estudio y se convierte en forma de operar. El alumno toma tareas reales, ideas pendientes, problemas de trabajo o proyectos personales y los transforma en procesos claros.

Esta fase es crucial porque muchas personas aprenden conceptos de IA pero no cambian nada en su vida diaria. Saben que es un prompt, pero siguen trabajando igual. Saben que ChatGPT puede ayudar, pero solo lo usan para respuestas sueltas. La fase dos rompe eso: cada alumno debe crear workflows propios.

## Que significa aplicar IA al trabajo

Aplicar IA al trabajo no es reemplazar criterio humano. Es rediseñar tareas para que la IA ayude donde aporta valor: organizar informacion, generar borradores, comparar opciones, crear checklists, revisar documentos, transformar formatos, preparar reuniones, sintetizar fuentes, idear proyectos, detectar riesgos y acelerar ciclos de trabajo.

La pregunta no es "que puedo pedirle a ChatGPT". La pregunta es "que parte de mi trabajo tiene entrada, proceso, salida y revision". Cuando una tarea tiene esas cuatro piezas, puede convertirse en workflow.

Ejemplos:

- Convertir notas desordenadas en acta.
- Preparar un informe semanal.
- Generar una presentacion desde documentos.
- Resumir feedback de clientes.
- Crear propuestas comerciales.
- Diseñar un plan de proyecto.
- Revisar una decision.
- Convertir una idea en requisitos.
- Preparar contenido educativo.

## Llevar ideas a cabo

Una idea suele fallar porque esta demasiado abierta. "Quiero crear una formacion", "quiero automatizar mi negocio" o "quiero hacer un agente" no son proyectos todavia. En esta fase se aprende a convertir una idea en:

- Problema.
- Usuario.
- Resultado.
- Restricciones.
- Primer entregable.
- Version minima.
- Pasos.
- Criterio de exito.

La IA ayuda a pensar, pero el alumno debe decidir. Un buen prompt para ideas no pide "dame ideas". Pide "convierte esta idea en tres versiones posibles, separa alcance, dificultad, herramientas necesarias, riesgos y primer paso".

## Herramientas principales de esta fase

La herramienta central es ChatGPT o Claude como copiloto de pensamiento y produccion. Obsidian es el espacio donde se guardan decisiones, prompts, workflows y documentos. Las plantillas de la boveda ayudan a convertir cada idea en formato reusable.

## Actividad principal

El alumno elige tres tareas reales:

1. Una tarea de documentacion.
2. Una tarea de decision.
3. Una idea que quiera llevar a cabo.

Por cada una crea:

- Descripcion de la tarea.
- Problema que resuelve.
- Entrada necesaria.
- Prompt inicial.
- Workflow paso a paso.
- Checklist de revision.
- Resultado esperado.
- Error comun.
- Version mejorada.

## Resultado de la fase

La fase termina con una carpeta o conjunto de notas de workflows personales. El alumno ya tiene material propio: prompts, procesos, documentos y primeras ideas transformadas en proyectos. Esta es la base para fase 03.

## Criterios para pasar a la fase 03

El alumno puede pasar a construccion cuando tiene al menos tres workflows propios documentados y una idea convertida en proyecto minimo. No basta con decir "quiero hacer una app" o "quiero automatizar informes". Debe tener problema, usuario, entrada, salida, herramientas candidatas y criterio de terminado.

La señal clave es que la idea ya no depende de motivacion. Tiene pasos. Si mañana otra persona leyera la nota, entenderia que construir primero. Esa claridad permite entrar en Codex, n8n, GitHub Skills o Gemini sin improvisar.

## Como impartir esta fase

Esta fase funciona muy bien con talleres. Cada alumno trae tareas reales. El profesor ayuda a bajarlas a procesos. Despues se comparte una version antes y despues. La comparacion enseña mucho: una peticion vaga frente a un workflow con entrada, pasos, revision y entrega.

Tambien conviene trabajar ideas personales. Una idea se divide en versiones: version documento, version workflow, version proyecto tecnico y version produccion. Asi el alumno aprende que no todas las ideas empiezan construyendo software.

## Errores frecuentes

El primer error es querer automatizar una tarea que aun no se entiende. El segundo es pedir ideas infinitas sin elegir ninguna. El tercero es confundir output bonito con utilidad real. El cuarto es no revisar privacidad cuando se usan datos de trabajo.

## Señal de aplicacion real

El alumno empieza a ahorrar tiempo o mejorar calidad en tareas reales. Tambien empieza a crear su propio lenguaje de trabajo: plantillas, checklists, prompts, notas y criterios. En ese momento la IA deja de ser novedad y se convierte en sistema.

## Clasificacion por ordenador y sistema operativo

Antes de convertir esta nota en una practica, laboratorio, documento o proyecto para otra persona, clasificala segun el ordenador del alumno y el nivel tecnico de ejecucion. Usa estas guias:

- [[../10_GUIAS_WINDOWS_MAC_LINUX/Windows]] para alumnos que trabajen con PowerShell, rutas `C:\...`, OneDrive, Git for Windows, Node.js, Python o Docker Desktop.
- [[../10_GUIAS_WINDOWS_MAC_LINUX/macOS]] para alumnos que trabajen con Terminal/zsh, rutas `/Users/...`, Homebrew, permisos de macOS o Apple Silicon.
- [[../10_GUIAS_WINDOWS_MAC_LINUX/Linux]] para alumnos que trabajen con Bash, rutas `/home/...`, gestores `apt`, `dnf` o `pacman`, permisos, servicios y Docker Engine.
- [[../10_GUIAS_WINDOWS_MAC_LINUX/Compatibilidad_de_proyectos]] para clasificar la practica como Nivel A, B, C, D o E.
- [[../10_GUIAS_WINDOWS_MAC_LINUX/Checklist_entrega_multisistema]] para comprobar que cualquier persona pueda seguirla sin depender de explicaciones orales.

Regla de entrega: si esta nota requiere terminal, Git, Node.js, Python, Docker, API keys, n8n, GitHub, Codex, Claude Code, Gemini o cualquier cuenta externa, debe indicar claramente que necesita el alumno, donde ejecutarlo, que salida esperar y como detectar errores en Windows, macOS y Linux.

## Preguntas que debe poder responder el alumno

- Que estoy intentando mejorar.
- Por que esta nota me ayuda.
- Que parte puedo aplicar hoy.
- Que artefacto voy a producir.
- Como sabre que funciona.
- Que puede fallar.
- Que herramienta no debo usar todavia.
- Que evidencia voy a guardar.
- Como lo explicaria a un cliente, jefe, compañero o alumno.

Si no puede responder alguna, no pasa nada. Esa pregunta se convierte en tarea.

## Criterio de clase inolvidable

Para que esta nota se convierta en una clase que impacte, necesita cinco momentos:

1. Reconocimiento: el alumno ve un problema real suyo.
2. Claridad: entiende el modelo mental.
3. Accion: produce algo pequeño.
4. Tension: algo se rompe.
5. Dominio: lo repara y lo explica.

Sin tension no hay aprendizaje profundo. Sin reparacion no hay confianza. Sin explicacion no hay transferencia.

## Criterio de proyecto inolvidable

Para que un proyecto derivado de esta nota sea memorable, debe tener:

- Nombre claro.
- Resultado visible.
- Dificultad honesta.
- Evidencia.
- Error reparado.
- Mejora respecto a la version inicial.
- Utilidad para alguien real.
- Posibilidad de enseñarse en portfolio.
